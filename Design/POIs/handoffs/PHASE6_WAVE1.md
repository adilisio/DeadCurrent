## Plan clarifications made while preparing this wave

The Integrator made these calls so the packages could be written without contradiction. Anthony reviews them before launch (they are also in `Design/ANTHONY_CHECKLIST.md`).

1. **The kit's gym is its own dev map, `Lvl_KitGym`, not a corner of the Pointe Sombre blockout.** The plan's VS-05 says "a kit gym (a corner of the blockout or `Lvl_TestGym`)" and forbids WP-KIT from touching map scripts, but `Lvl_PointeSombre` does not exist until VS-04, which waits for VS-03. A separate map generated by the kit's own script (`Tools/EditorScripts/kit/build_kit_gym.py`) keeps WP-KIT independent of VS-03/VS-04 and of the shared map scripts. `Tools/Maps.bat` registers it as a **development** map (reviewable and playable, never cooked or run by the production test loop).
2. **The kit is verified by a headless script, not by `Map.Sombre.KitGym`.** That test name needs the Sombre map and a `Source/**` test file, which WP-KIT may not create. WP-KIT ships `kit/verify_kit.py` (run with `Tools\RebuildContent.bat kit\verify_kit`; a failed check is a Traceback, which fails the run) and review captures of `Lvl_KitGym`. The plan's integration test for the kit on the real island is `Map.Sombre.Greybox` (VS-08).
3. **The Gemini research has its own folder and package.** The plan lists "Gemini survey (docs only)" as an input to WP-KIT; here it is an explicit, separately owned deliverable (`Design/Kits/research/`).

None of these changes scope, ownership of any shipped file, or the plan's Definition of Done.

## Launching an agent (what to paste)

Create the worktree yourself, or let the agent do it from its handoff. Then give the agent this prompt, with its package name:

> You are the `<role>` for DEAD CURRENT Phase 6, package `<WP-NAME>`. Work in the worktree `C:\DeadCurrent_wt\<package>` on branch `vs/<package>`, created from `origin/main` (the wave-handoff commit: VS-02 `e833811` plus these handoff files). Read `CLAUDE.md`, `Design/POIs/README.md`, `Design/POIs/handoffs/PHASE6_WAVE1.md`, and your handoff `Design/POIs/handoffs/sombre_<WP-NAME>.md`, then do exactly what the handoff says. Stay inside its owned files. Stop at its stop conditions and write the reason at the top of its Handoff Notes. Commit only on your branch; push only your branch; never push `main`. Do not start any task that is not in your handoff.

Worktree creation, per package:

```
git fetch origin
git worktree add C:\DeadCurrent_wt\sys-portal -b vs/sys-portal origin/main
git worktree add C:\DeadCurrent_wt\kit -b vs/kit origin/main
git worktree add C:\DeadCurrent_wt\kit-research -b vs/kit-research origin/main
```

`origin/main` at launch is the wave-handoff commit: VS-02 (`e833811`) plus these handoff files, so each worktree carries its own handoff. Check inside each worktree: `git merge-base --is-ancestor e833811 HEAD && echo ok`.
